Claude Code → OpenCode Delegation Bridge

Project version: 1.10.0
Validated Claude Code version: 2.1.299
Validated OpenCode version: 2.0.31 (1.x still supported)
Validated delegated model: muse-spark-1.3-contributor-free

Validated behavior:
- Opus 5.5 session (fresh `claude -p`, skill not named in the prompt): automatic skill selection and delegation to OpenCode through the bundled worker, with the task in the Goal/Files/Done-when template and no model passed (OpenCode default used).
- After delegation: the main Opus session checked the file itself and the diff against the worker's baseline, and did not commit.
- Sonnet 5.5 session: no delegation; Claude Code performed the file write itself.
- Worker: task passed on stdin reaches OpenCode literally; deny rules from OPENCODE_CONFIG_CONTENT (git, rm -rf, user deny file) block the command, including commands rewritten by the rtk plugin.
- Worker: refuses to run outside git; reports only the changes made during the run; exits 3 when OpenCode hit a denied or auto-rejected permission (OpenCode itself exits 0).
- OpenCode reads the project's CLAUDE.md.
- Worker: a correction sent with OPENCODE_WORKER_SESSION resumes the same OpenCode session, which keeps the earlier context; the report shows only that round's changes.
- Worker: uses OpenCode's default model; an explicit OPENCODE_WORKER_MODEL is refused before dispatch when missing from `opencode models`.
- Worker read-only mode (OPENCODE_WORKER_MODE=read): OpenCode's plan agent answered a question about the worker with correct file:line citations and left the tree unchanged; a command outside the bash allowlist was denied and the model retried with an allowed one. With the same permissions and the build agent, a write through bash, a write to .opencode/plans/ and a new file were all denied.
- Worker 1.8.0: with `--format json`, a real edit run (add a function and its test) reported in 982 characters: final answer, tool count, OpenCode tokens, diffstat and session; the transcript stayed in the log file.
- OpenCode's free tier rejects a run whose bash tool is denied outright ("can only be used from within OpenCode"); an allowlist keeps the tool and works.
- skills CLI (`npx skills add`) discovers the skill and copies scripts/ with the executable bit.
- Worker on OpenCode 2: runs with --standalone so deny rules from OPENCODE_CONFIG_CONTENT apply (the default background service ignores them); edit run, deny of git commit, session lookup by title and session resume all worked; deny hits (`Permission denied: shell`) and auto-rejects exit 3.
- Worker 1.10.0 (OPENCODE_WORKER_CHECK, inline diff, short SKILL.md): delegated Opus sessions went skill -> one worker call -> one review command -> answer; a test-suite task cost about 30% less than Opus alone, a scriptable 12-module change cost the same.
